# Единый стиль левых панелей (после ee20ca0)

> **Статус: анализ + предложение.** Кода ещё нет — документ описывает, что
> именно разъезжается между разделами, какую единую спецификацию предлагается
> принять и в каком порядке её внедрять.

После `ee20ca0` («unified workspace layout») **оболочка** у всех разделов общая:
`WorkspaceLayout` даёт один контейнер, одну левую панель со слотами
(`title · action · toolbar · body`), центр и правую панель. Но **наполнение**
левой панели каждый раздел по-прежнему рисует своими классами, доставшимися от
дореформенных панелей. В результате рамка одна, а содержимое внутри разное:
строки разной высоты и цвета, разные шрифты, две несовместимые реализации
поиска, у базы знаний поиска нет вовсе. Переключение раздела читается как
переход в другое приложение, а не как смена содержимого одной панели.

---

## 1. Что сейчас разъезжается

### 1.1. Строка списка/дерева — четыре разных набора правил

| | Чат `.chat-list-item` | База знаний `.tree-row` | Файлы `.file-tree-row` | Настройки/Админ `.settings-nav__item` |
|---|---|---|---|---|
| Файл | `chatPanel/styles/sidebar.css` | `knowledgeBasePanel/styles/tree.css` | `filesPanel/filesPanel.css` | `common/settingsShell.css` |
| padding | `9px 14px` | `9px 14px` + отступ уровня | `7px 14px` + отступ уровня | `10px 16px` |
| min-height | — | `36px` | `32px` | `40px` |
| высота в браузере | 41px | 55px | 46px | 40px |
| font-size | `0.88rem` | `0.88rem` | `0.86rem` | `0.88rem` |
| цвет текста | `--kb-accent` | `--kb-accent` | `--kb-text` | `--kb-accent` |
| font-weight | 500 | 500 | 400 | 500 |
| разделитель | `border-bottom: --kb-border` | `border-bottom: --kb-border-light` | нет | `border-bottom: --kb-border-light` |
| маркер выбора | нет (только заливка) | нет (только заливка) | полоса `3px --kb-accent` слева | полоса `3px --kb-accent` слева |
| выбранная строка | фон + 700 | фон + 700 | фон + 700 + цвет accent | фон + 700 |
| отступ уровня | — | `--tree-indent: 16px` | `--file-tree-indent: 12px` | — |
| действия строки | `icon-btn` 22px, opacity .5 | свой `.tree-row__del`, opacity 0 → .6 | нет | нет |
| иконки действий | текстовые глифы `✎` `✕` | текстовый глиф `✕` | — | — |
| шеврон | — | 16px | 12px | — |

Самое заметное на глаз:

- **Три из четырёх списков красят весь текст в акцентный фиолетовый**
  (`--kb-accent`), и только дерево файлов — в обычный `--kb-text`. Из-за этого
  чат и база знаний выглядят «списком, где выделено всё», а файлы — спокойным
  деревом. При переключении разделов меняется общий тон панели.
- **Высота строки гуляет 40 → 41 → 46 → 55px** (замеры в браузере, см. 1.4),
  шрифт 0.86 ↔ 0.88rem: на одной и той же высоте панели помещается разное число
  строк, ритм скачет.
- **Маркер выбранной строки разный**: в файлах и настройках слева акцентная
  полоса, в чате и базе знаний — только заливка.
- **Разделители строк**: три варианта — тёмная линия, светлая линия, никакой.

### 1.2. Поиск над списком — две почти одинаковые реализации и одна дыра

| | Чат `ChatSearch` | Файлы `FileSearch` | База знаний | Настройки |
|---|---|---|---|---|
| Компонент | `chatPanel/ChatSearch.jsx` (128 стр.) | `filesPanel/FileSearch.jsx` (127 стр.) | **нет** | нет |
| Кнопка-триггер | плашка во всю ширину, `border-radius: 20px`, иконка + подпись | круглая кнопка 28×28, только иконка | — | — |
| Поле ввода | высота 32px, радиус 16, шрифт `0.84rem` | высота 28px, радиус 14, шрифт `0.82rem` | — | — |
| Выпадающий список | min-width 320, max-height 420, строки `align-items: flex-start`, `padding: 8px 10px` | min-width 360, max-height 360, строки `align-items: center`, `padding: 7px 10px` | — | — |
| CSS | `chatPanel/styles/search.css` (≈130 строк) | `filesPanel/filesPanel.css` (≈115 строк) | — | — |
| i18n | `chat:sidebarSearch.*` | `files:search.*` | — | — |

Оба компонента уже построены на общем `useSearchDropdown` — то есть **вся
логика общая, а разошлись именно разметка и стиль**: два набора классов
(`chat-search*` / `file-search*`), два размера, две формы триггера, два набора
ключей i18n с одинаковым смыслом («Поиск…», «Ничего не найдено», «Закрыть
поиск»).

Плюс к этому:

- **У базы знаний поиска по дереву нет вообще** — тулбар-слот пуст, и панель
  визуально «короче» на одну строку, хотя дерево там самое длинное. При этом
  готовый эндпоинт уже есть: `documentsApi.searchByName` (им пользуется
  `AtMentionDropdown`), бэкенд трогать не нужно.
- **Триггер в файлах — круглая кнопка 28px в пустой строке во всю ширину**:
  строка тулбара занята, а выглядит незаполненной.

### 1.3. Отступы: пять разных левых полей в одной панели

| Элемент | Класс | Левое поле |
|---|---|---|
| Шапка панели | `.workspace__side-head` | `0.85rem` ≈ 13.6px |
| Главное действие | `.workspace__side-action` | `0.85rem` ≈ 13.6px |
| Тулбар | `.workspace__side-toolbar` | `0.6rem` ≈ 9.6px |
| Поиск в чате | `.chat-search { margin: 0 1rem … }` | 9.6 + 16 = **25.6px** |
| Строки списков/деревьев | `.chat-list-item` и др. | 14px (16px в настройках) |

То есть кнопка «Новый чат», плашка поиска под ней и строки списка стоят на трёх
разных вертикалях — в одной панели. `ChatSearch` держит собственный внешний
`margin`, хотя отступ уже задаёт слот `workspace__side-toolbar`.

Ещё мелочи того же рода:

- верхний отступ тела: у дерева файлов `padding: 0.5rem 0`, у остальных `0`;
- ширина панели: `--ws-left-width: 268px` у всех, `290px` у файлов
  (`.workspace--files`) — при переключении раздела граница панели прыгает на
  22px;
- пустое состояние есть только у файлов (`.file-tree-hint`: «Пусто», «Загрузка…»);
  пустой чат-лист и пустое дерево базы знаний не показывают ничего.

### 1.4. Замеры в браузере (Chromium 1440×900, сид `db/sample-data.sql`)

Не расчёт по CSS, а `getBoundingClientRect` живого приложения — по левой панели
активного раздела:

| | Чат | База знаний | Файлы | Настройки |
|---|---|---|---|---|
| Ширина панели | 268px | 268px | **290px** | 268px |
| Верх первой строки списка (от верха панели) | **163px** | 107px | 107px | **58px** |
| Левый край виджета в тулбаре | 26px | — | **10px** | — |
| Левый край кнопки действия | 14px | 14px | — | — |
| Левый край текста строки | 14px | 14px | 14px | **16px** |
| **Фактическая высота строки** | **41px** | **55px** | **46px** | **40px** |

Отсюда два вывода сверх пункта 1.1:

- **Список начинается на разной высоте** — от 58 до 163px от верха панели, и
  граница панели при переходе в «Файлы» сдвигается на 22px. Именно это читается
  как «панель прыгнула», даже если не разглядывать строки.
- **Высоты строк не те, что написаны в CSS.** В `min-height` заявлены 36 (база
  знаний) и 32 (файлы), а рендерятся 55 и 46. Причина: **глобального
  `box-sizing: border-box` в проекте нет** (в `index.css`/`App.css` его не
  задают), и для `div`-строк `min-height` считается по content-box, к нему
  сверху прибавляются `padding` и `border` (36 + 9 + 9 + 1 = 55; 32 + 7 + 7 = 46).
  А строка настроек — это `<button>`, которому UA-стиль браузера ставит
  `border-box`, поэтому её 40px — честные 40px. То есть одинаково выглядящие
  правила дают разный результат в зависимости от того, `div` строка или `button`.
  Поэтому у общего примитива `box-sizing: border-box` — обязателен (см. 2.2).

### 1.5. Что уже унифицировано (на это опираемся)

- Главное действие панели: и чат, и база знаний используют
  `btn btn--primary` + `IconPlus` из `common/buttons.css` — здесь расхождений
  нет, менять нечего.
- Шапка панели, тумблер сворачивания, рельс, ширины через CSS-переменные,
  адаптив — всё в `WorkspaceLayout`.
- Вся логика поиска — в общем `useSearchDropdown`.
- Иконки — общий набор `icons/index.jsx` (кроме двух мест с текстовыми глифами,
  см. 1.1).

**Вывод.** Расхождения — исключительно презентационные и локализованы в четырёх
CSS-блоках и двух компонентах поиска. Ни навигацию, ни API, ни состояние
трогать не требуется.

## 2. Целевая спецификация левой панели

Одна панель, одинаковая во всех разделах; разделы отличаются только тем, **что**
в строках, а не тем, **как** строка выглядит.

### 2.1. Токены (в `.workspace`, рядом с `--ws-left-width`)

```css
--ws-gutter: 14px;      /* единое левое поле: шапка, действие, тулбар, строки */
--ws-row-min-h: 34px;   /* высота строки */
--ws-row-pad-y: 8px;
--ws-row-font: 0.86rem;
--ws-indent: 14px;      /* отступ уровня дерева */
--ws-left-width: 280px; /* одна ширина на все разделы */
```

Раздел может переопределить токен своим модификатором `.workspace--*`, но это
исключение, требующее комментария с причиной. Заявка уже есть одна: у файлов
пути глубокие, для них уместен `--ws-indent: 12px`.

### 2.2. Примитив строки — `.ws-item` (новый `common/sidePanel.css`)

```css
.ws-item {
  display: flex;
  align-items: center;
  gap: 6px;
  box-sizing: border-box; /* иначе min-height считается по content-box, см. 1.4 */
  min-height: var(--ws-row-min-h);
  padding: var(--ws-row-pad-y) var(--ws-gutter) var(--ws-row-pad-y)
           calc(var(--ws-gutter) + var(--depth, 0) * var(--ws-indent));
  font-size: var(--ws-row-font);
  font-weight: 500;
  color: var(--kb-text);
  cursor: pointer;
  transition: background 0.1s, box-shadow 0.1s;
}
.ws-item:hover { background: var(--kb-accent-light); }
.ws-item--active {
  background: var(--kb-accent-bg);
  color: var(--kb-accent);
  font-weight: 700;
  box-shadow: inset 3px 0 0 var(--kb-accent); /* акцентная полоса слева */
}
```

Принятые решения (то, что сейчас различается — здесь фиксируется один вариант):

1. **Цвет строки в покое — `--kb-text`**, акцентный только у выбранной. Вариант
   дерева файлов, самый спокойный; чат/база знаний/настройки перекрашиваются.
2. **Маркер выбора — акцентная полоса слева + заливка + 700.** Полоса делается
   `box-shadow: inset`, а не `border-left`: `border-left` у базы знаний занят
   индикаторами drag-drop (`.tree-row--drop-*`), и они бы конфликтовали.
3. **Разделителей строк нет.** Сейчас три разных варианта; плотность задаётся
   высотой строки, а линии в дереве с отступами только шумят.
4. **Элементы строки** — общие модификаторы: `.ws-item__chevron` (16px),
   `.ws-item__icon`, `.ws-item__label` (`flex: 1` + ellipsis),
   `.ws-item__actions`. Дереву файлов нужен `.ws-item--nowrap`: там строка
   тянется на `width: max-content` (двухосевой скролл), поэтому метка не
   сжимается и не обрезается ellipsis'ом.
5. **Действия строки — только `icon-btn`** из `buttons.css`, 22×22, `opacity: .5`
   → 1 при наведении на строку и при `:focus-visible`. Собственный
   `.tree-row__del` удаляется; текстовые глифы `✎`/`✕` заменяются на
   SVG-иконки из общего набора (в чате и базе знаний).
6. **Пустое/загрузочное состояние — общий `.ws-hint`** (нынешний
   `.file-tree-hint`), появляется и в чате, и в дереве базы знаний.

### 2.3. Общий поиск панели — `<PanelSearch>` (новый `common/PanelSearch.jsx`)

`ChatSearch` и `FileSearch` схлопываются в один компонент: логика уже общая
(`useSearchDropdown`), в разделах остаётся только «чем искать» и «как рисовать
строку результата».

```jsx
<PanelSearch
  placeholder={t('search.placeholder')}
  hint={t('search.hint')}
  search={(q, signal) => documentsApi.searchByName(q, 15, signal)}
  getKey={(node) => node.id}
  renderItem={(node, query) => <>…</>}
  onSelect={openNode}
/>
```

`PanelSearch` владеет: кнопкой-триггером, полем ввода, порталом выпадающего
списка, сообщениями «Поиск…» / «Ничего не найдено» / подсказкой, размерами и
классами (`panel-search*`).

Единый вид (вместо двух нынешних):

- **триггер** — во всю ширину тулбара, иконка + подпись, на общих классах
  `btn btn--ghost btn--sm` (свои `border/radius` у `.chat-search__trigger` и
  `.file-search__trigger` уходят: вид кнопок живёт только в `buttons.css`);
- **поле** — высота 32px, радиус 16, шрифт `0.84rem`;
- **список** — `min-width: max(ширина якоря, 340px)`, `max-height: 420px`,
  строки `padding: 8px 10px`, `align-items: flex-start`.

Общие подписи («Поиск…», «Ничего не найдено», «Закрыть поиск») переезжают в
`common.json` (`panelSearch.*`), в разделах остаются только свои placeholder и
подсказка.

**Поиск появляется и в базе знаний** — на `documentsApi.searchByName`, без
изменений на бэкенде. У настроек/админки тулбара по-прежнему нет: список групп
короткий и фиксированный (слот необязателен — но если он есть, то это всегда
`PanelSearch`).

### 2.4. Итоговая раскладка панели (одинаковая везде)

```
┌────────────────────────────┐
│ Заголовок           [⇤]    │  workspace__side-head   (gutter 14px)
├────────────────────────────┤
│ [ + Создать          ]     │  workspace__side-action (gutter 14px)
│ [ 🔍 Поиск…          ]     │  workspace__side-toolbar(gutter 14px)
├────────────────────────────┤
│ ▸ 📁 Строка                │  .ws-item, 34px, 0.86rem
│ ▍▸ 📄 Выбранная строка     │  .ws-item--active
└────────────────────────────┘
```

Критерий приёмки: при переключении разделов **не должны сдвигаться** граница
панели, левое поле содержимого, высота строки и типографика; меняется только
состав строк и наличие кнопки действия.

Про вертикальное начало списка (сейчас разброс 58…163px, см. 1.4): полностью
оно не выровняется — у файлов и настроек нет кнопки создания, и придумывать её
не надо. Но после этапов 1–3 разброс сводится к одному осмысленному различию
«есть кнопка действия / нет»: у чата и базы знаний одинаковые
шапка + действие + поиск, у файлов — шапка + поиск, у настроек — только шапка.
Сейчас же разъезжаются ещё и высота тулбара, и отступы внутри него.

## 3. Порядок внедрения

Разбито так, чтобы каждый этап был самостоятельным PR с проверяемым результатом.

**Этап 1 — токены и отступы (быстрый, чисто CSS).**
Ввести токены из 2.1 в `common/workspaceLayout.css`, перевести на
`--ws-gutter` шапку, действие и тулбар; убрать `margin` у `.chat-search`;
свести `--ws-left-width` к одному значению (убрать переопределение в
`.workspace--files`); убрать `padding: 0.5rem 0` у `.files-panel-tree`.
Проверяется замерами из 1.4: левый край виджета в тулбаре, кнопки действия и
текста строки должен стать одинаковым (14px) во всех разделах.

**Этап 2 — `common/sidePanel.css` и перевод строк.**
Добавить `.ws-item*`, `.ws-hint`; перевести на них `ChatList`, `TreeNode`,
`FileTreeNode`, `settings-nav__item`. В панелях остаётся только специфика:
drag-drop у базы знаний, `width: max-content` у файлов. Удалить
`.chat-list-item*`, базовые правила `.tree-row`, `.file-tree-row`,
`.settings-nav__item`.

**Этап 3 — `common/PanelSearch.jsx` + `panelSearch.css`.**
Перевести чат и файлы, удалить `ChatSearch.jsx`, `FileSearch.jsx` и их CSS-блоки;
добавить поиск в базу знаний; общие ключи i18n — в `common.json` (`en` + `ru`).

**Этап 4 — действия строк и мелочи.**
`icon-btn` + SVG-иконки вместо глифов, `.tree-row__del` удалить, пустые
состояния в чате и базе знаний, единый `.ws-item--nowrap` для файлов.

**Этап 5 — уборка и проверка.**
Вычистить осиротевшие классы, обновить `CLAUDE.md` (раздел «Frontend
conventions»: левая панель — `.ws-item` + `PanelSearch`, новых панельных
семейств не заводить), сверить скриншоты четырёх разделов.

Оценка: этапы 1 и 4 — по несколько десятков строк; 2 и 3 — основной объём
(≈ −450 строк CSS/JSX дублей, + ≈ 200 строк общего кода).

## 4. Риски

| Риск | Решение |
|---|---|
| Индикаторы drag-drop базы знаний используют `border-left` | Маркер выбора делать `box-shadow: inset`, `border-left` оставить за DnD (см. 2.2) |
| Дерево файлов ломается от `flex: 1` на метке (автоскролл обрезает короткие имена — уже чинилось) | Модификатор `.ws-item--nowrap`, поведение `width: max-content` сохранить как есть |
| Смена цвета строк на `--kb-text` — заметное изменение вида чата и базы знаний | Это и есть цель («разделы выглядят одинаково»); проверить контраст выбранной строки на `--kb-accent-bg` |
| Единая ширина 280px ужмёт дерево файлов | У файлов есть горизонтальный скролл; при жалобах вернуть переопределение токена одной строкой |
| Разъезд заново | `CLAUDE.md`: строки левых панелей — только `.ws-item`, поиск — только `PanelSearch`; новых `*-item`/`*-search` семейств не заводить (та же политика, что уже принята для кнопок и модалок) |

## 5. Что в объём не входит
