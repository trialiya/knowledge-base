## 1. Что есть сейчас (анализ)

### 1.1. Общая оболочка (`App.js` + `App.css`)

- Верхняя панель вкладок `.app-tabs`: слева иконки-вкладки (💬 📚 📁), по центру
  `GlobalSearch`, справа `HeaderMenu` (обновить · язык · админ · настройки).
- `main` держит `.app-tab-panel` для каждого view. Чат и База знаний
  смонтированы всегда и скрыты через CSS (`--hidden`), Files/Admin/Settings
  монтируются по адресу.
- Навигация целиком в `useAppNavigation` (URL — единственный источник правды).

### 1.2. Три раздела — три независимые раскладки

Каждый раздел сам рисует свой контейнер (`margin: 1rem`, `border-radius`,
`box-shadow`) и свой сплит «левая панель + основная область». Код и CSS
дублируются:

| Раздел | Контейнер | Левая панель | Основная | Правая панель |
|--------|-----------|--------------|----------|---------------|
| Чат | `.chat-app-container` | `.chat-list` (260px, `ChatList`) | `.chat-window` | `.chat-attachment-panel` (300px, **есть**, тумблер в шапке) |
| База знаний | `.knowledge-base-container` → `.kb-main` | `.kb-tree` (`TreeNode`) | `.kb-preview` (`DocumentDetail`/`FolderDetail`/`SearchResults`) | нет (summary/вложения — вкладки внутри детали) |
| Файлы | `.files-panel-container` → `.files-panel-main` | `.files-panel-left` (280px, `FileTree`) | `.files-panel-preview` (`FileContent`) | нет |

Наблюдения:
- **Левые панели нескрываемы**, ширины зашиты (260 / «flex» / 280 px).
- **Правая панель есть только в чате** (`chat-attachment-panel`), реализована
  локально в `ChatWindow.jsx`, со своей вёрсткой и своими классами.
- **Summary и вложения** в Базе знаний живут во вкладках `DetailTabs`
  (`SUMMARY` / `CONTENT` / `ATTACHMENTS`) внутри `DocumentDetail` — то есть
  «доп. инфа» отнимает место у основного контента, а не вынесена вбок.
- Кнопки «Новый чат» / «＋ Создать» / тулбары левых панелей — свои в каждом
  разделе (`.new-chat-button`, `.kb-new-doc-button`, `.files-panel-toolbar`).

### 1.3. Что уже переиспользуемо (на это опираемся)

- `components/common/AttachmentPanel.jsx` — **общая** панель вложений
  (принимает `ownerType` = `chat` | `document`, `ownerId`, `compact`,
  `onCountChange`). Уже используется и в чате, и в KB.
- `components/common/ModalShell`, `buttons.css` (`btn`, `icon-btn`),
  `SettingsShell` — общая chrome, на которую велено мигрировать (см. CLAUDE.md).
- Дизайн-токены в `index.css` (`--kb-accent`, `--kb-border`, `--kb-bg`,
  `--kb-radius`…). Тёмной темы нет — «единый стиль» здесь про раскладку и
  chrome, не про темизацию.
- Набор иконок в `icons/index.jsx` — есть `IconChevron*`, `IconSliders`,
  `IconPaperclip`, `IconX` и т.д. (кнопки сворачивания рисовать не с нуля).

## 2. Целевая архитектура

### 2.1. Единая оболочка рабочей области — `WorkspaceLayout`

Новый общий компонент `components/common/WorkspaceLayout.jsx` (+
`common/workspaceLayout.css`), который держит **три слота** и всю механику
сворачивания:

```
┌──────────────────────────────────────────────────────────────┐
│  app-tabs (без изменений: вкладки · поиск · меню)              │
├───────────┬──────────────────────────────────┬───────────────┤
│  LEFT      │            CENTER                 │    RIGHT      │
│  (rail →   │         основная область          │  (drawer,     │
│  скрывается)│                                   │  свёрнута по  │
│            │                                   │  умолчанию)   │
└───────────┴──────────────────────────────────┴───────────────┘
```

API (slot-props, каждый раздел передаёт своё содержимое):

```jsx
<WorkspaceLayout
  viewKey="chat" | "knowledge" | "files"   // ключ для персиста состояния
  left={{
    title,                    // заголовок панели (для строки-«рельса»)
    action,                   // главная кнопка («Новый чат» / «Создать»)
    toolbar,                  // поиск по списку/дереву (ChatSearch/FileSearch)
    children,                 // сам список/дерево
  }}
  center={centerNode}         // шапка + контент + (для чата) поле ввода
  right={{
    tabs: [{key,label,badge,node}],  // «Вложения» / «Summary» / «Инфо»
    defaultCollapsed: true,
  }}
/>
```

`WorkspaceLayout` берёт на себя:
- контейнер (`margin`, `radius`, `shadow`) — **один** вместо трёх;
- кнопки-тумблеры сворачивания левой и правой панели;
- ширины через CSS-переменные (`--ws-left-w`, `--ws-right-w`) — единые;
- анимацию сворачивания и «рельс» (узкую полоску с иконкой разворачивания);
- персист состояния (свёрнута/развёрнута, активная вкладка справа) по `viewKey`;
- адаптив: на узком экране правая (а затем левая) панель становится оверлеем.

### 2.2. Состояние сворачивания

Отдельный хук `hooks/usePanelState.js`:
- `leftCollapsed`, `rightCollapsed`, `rightTab` — per-`viewKey`;
- персист в `localStorage` (новые ключи в `constants/storage.js`:
  `kb.ui.panels`);
- дефолты: левая — развёрнута, правая — **свёрнута**.

Опция на будущее — поднять эти флаги в URL/`useAppNavigation` (как `docTab`),
но на первом этапе достаточно `localStorage`: это чисто UI-состояние.

### 2.3. Наполнение правой панели по разделам

| Раздел | Вкладки правой панели |
|--------|-----------------------|
| Чат | **Вложения** (`AttachmentPanel` chat) · **Инфо** (модель/режим/дата/кол-во сообщений) |
| База знаний | **Summary** (AI-summary + «О документе») · **Вложения** (`AttachmentPanel` document) · **Инфо** (путь, даты, история) |
| Файлы | **Инфо** (метаданные файла: размер, путь, тип) · при наличии — summary/вложения файла |

Ключевой перенос: summary/вложения Базы знаний **уезжают из вкладок
`DetailTabs` в правую панель**. В центре у документа остаётся заголовок +
контент (редактор). `DetailTabs` (`SUMMARY`/`CONTENT`/`ATTACHMENTS`)
упрощается — вкладка `CONTENT` становится основным телом, `SUMMARY`/
`ATTACHMENTS` переезжают вправо.

## 3. Поэтапный план работ

Дробим на PR-порции (в духе migrate-on-touch: каждая порция самодостаточна и
проверяема). Порядок выбран так, чтобы каждый шаг оставлял приложение рабочим.

   CSS-переменные ширин, адаптив. Пока без подключения к разделам (можно

3. Общий компонент правой панели `RightPanel.jsx` (шапка с вкладками + тело +

**Проверка:** `yarnTest` зелёный; визуальный smoke через
`scripts/playwright-smoke.js` (компонент пока не в проде — только юнит).

### Этап 1. Файлы (самый простой раздел — обкатываем макет)

**Проверка:** открыть файл/каталог, свернуть/развернуть обе панели, обновить

### Этап 2. Чат
6. Переписать `ChatWindow.jsx` на `WorkspaceLayout`: `ChatList` → `left`,
   окно чата → `center`, вложения → `right` (вкладка «Вложения»,

**Проверка:** отправка сообщения, стриминг, поиск по чату (Ctrl+F не должен

### Этап 3. База знаний (самый крупный — перенос summary/вложений)

**Проверка:** просмотр/редактирование документа, генерация summary из правой

## 5. Риски и решения

| Риск | Решение |
|------|---------|
| Чат смонтирован всегда (скрыт CSS) — сворачивание не должно ломать `isActive`-фокус и Ctrl+F | Тумблеры вешать на клики, не на глобальные шорткаты; Ctrl+F оставить как есть, проверить отсутствие конфликта фокуса |
| Перенос summary/вложений KB может задеть `useDetailPanel`, `editorDirtyStore`, полноэкранный редактор | Переносить как есть (те же пропсы `AttachmentPanel`/`SummarySection`), менять только контейнер, не логику |
| Ширины/скролл дерева файлов (`width: max-content`) при новой оболочке | Сохранить внутренний горизонтальный скролл дерева; оболочка задаёт только ширину слота |
| Разъезд состояния между вкладками/перезагрузкой | Персист через `usePanelState` + дефолт «правая свёрнута» |
| Рост монолитных CSS (CLAUDE.md против этого) | Новые стили — в `common/workspaceLayout.css`; из панелей удалять переехавшее, не наращивать |
