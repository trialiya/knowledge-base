# Настройки — руководство пользователя

Панель **Настройки** позволяет просмотреть и управлять параметрами приложения, включая модели AI, параметры поиска и инструменты.

> 📘 **Где найти:** кнопка ⚙️ в правой части верхней панели приложения.

## 1. Структура настроек

Настройки разделены на несколько групп, каждая содержит связанные параметры:

- **Модели** — параметры AI-моделей и эмбеддингов
- **Поиск** — настройки семантического поиска
- **Инструменты** — режимы ассистента, редактирование файлов, интеграции MCP
- **Скрипты** — песочница инструмента `runScript`, её бюджеты и пробный запуск
- **Чат** — параметры диалога и истории

## 2. Группа «Модели»

Содержит информацию о доступных AI-моделях и параметрах эмбеддингов:

### Основные параметры

| Параметр | Описание |
|---|---|
| **Доступные модели** | Список моделей, которые можно выбрать в чате (например, claude-opus-5, claude-sonnet-5) |
| **Модель по умолчанию** | Модель, которая используется при создании нового чата |
| **Слабая модель (weak)** | Признак каждой модели: нужна ли ей обучающая половина руководства по скриптам. Помечен пилюлей `weak` в списке доступных моделей |
| **Модель суммаризации** | Модель, используемая для генерации AI Summary документов |
| **Модель эмбеддингов** | Модель для преобразования текста в векторы (используется в семантическом поиске) |

### Параметры суммаризации

Влияют на генерацию AI Summary:

| Параметр | Описание |
|---|---|
| **Минимум слов** | Минимальное количество слов в описании документа для разрешения суммаризации |
| **Максимум токенов** | Максимальная длина генерируемого summary (в токенах модели) |
| **Таймаут** | Максимальное время ожидания генерации summary |
| **Число попыток** | Количество попыток переподключения при ошибке |

### Инструменты саб-агента

Список инструментов, доступных для AI-агента при создании и обновлении документов.

> 💡 **Про флаг weak:** он не делает модель хуже или лучше и не влияет на то, что ей доступно. От него зависит только объём руководства по инструменту `runScript` в системном промпте: модели, помеченной `weak`, дописывается обучающая половина с примерами, остальным достаётся только справочник по `kb` и лимитам. Задаётся у каждой модели отдельно (`kb.chat.default-model.weak`, `kb.chat.models[].weak`), по умолчанию — `true`.

## 3. Группа «Поиск»

Параметры семантического поиска и гибридного поиска:

| Параметр | Описание | По умолчанию |
|---|---|---|
| **Режим поиска** | Выбор режима поиска по умолчанию (Hybrid, Keyword, Semantic) | Hybrid |
| **Семантический поиск** | Включить/выключить семантический поиск (доступно только когда активен профиль h2) | ✓ включён |
| **Порог семантического поиска** | Минимальное значение cosine similarity для результатов (0.0–1.0) | Зависит от конфигурации |
| **Вес ключевых слов** | Вес keyword-поиска при гибридном поиске | Зависит от конфигурации |
| **Вес семантики** | Вес semantic-поиска при гибридном поиске | Зависит от конфигурации |

> 💡 **На профиле h2:** семантический поиск отключен по умолчанию для уменьшения нагрузки на БД. Его можно включить в настройках.

## 4. Группа «Инструменты»

### Доступные инструменты

Первая секция группы — каталог того, что ассистент умеет вызывать. В шапке секции стоит счётчик и выпадающий список: выбираете инструмент, под списком открывается карточка выбранного.

| Элемент карточки | Что показывает |
|---|---|
| **Название и техническое имя** | Человекочитаемое название (то же, что в плашках вызовов под ответом ИИ) и рядом имя, которым инструмент называет модель — `searchDocuments`, `getFileTree` |
| **Описание** | Текст, который читает сама модель, решая, вызывать инструмент или нет — как есть, без пересказа |
| **Аргументы** | Имя, тип (`string`, `integer`, `array<string>`), пометка «обязательный»/«необязательный» и пояснение из схемы. Если у аргумента фиксированный набор значений (`hybrid`, `semantic`, `keyword`), они перечислены рядом |
| **Пилюля MCP** | Стоит у инструментов, пришедших с внешнего MCP-сервера, а не встроенных в приложение |

Список — не справочник «вообще», а то, что модели выдано **при текущей конфигурации**. Поэтому по нему видно и обратное: если правка файлов выключена, `createFile` и `editFile` в каталоге отсутствуют, а не показаны серым; выключенный `kb.script.enabled` убирает `runScript`, выключенный MCP — все инструменты внешних серверов.

### Ассистент

| Параметр | Описание |
|---|---|
| **Режим редактирования** | Разрешить/запретить AI редактировать файлы в репозитории |
| **Режим чтения** | Разрешить/запретить AI читать файлы из репозитория |
| **Режим создания документов** | Разрешить/запретить AI создавать документы в базе знаний |
| **Режим обновления документов** | Разрешить/запретить AI обновлять существующие документы |

### MCP (Model Context Protocol)

Если настроены внешние MCP-серверы:

| Элемент | Описание |
|---|---|
| **Список подключений** | Показывает имена подключённых MCP-серверов и тип транспорта (stdio, SSE, etc.) |
| **Статус** | Активное подключение или ошибка соединения |

Ключи и токены подключений **не отображаются** по соображениям безопасности.

### Вложения

| Параметр | Описание |
|---|---|
| **Максимальный размер файла** | Максимальный размер вложения в чат (в МБ) |
| **Максимальное количество файлов** | Максимальное количество одновременно загружаемых файлов |

## 5. Группа «Скрипты»

Здесь показано, как устроена песочница инструмента **`runScript`** — того самого, которым ассистент вместо десятка отдельных чтений обходит репозиторий одним JS-скриптом.

### Состояние

| Параметр | Описание |
|---|---|
| **Инструмент runScript** | Выдан ли инструмент модели вообще (`kb.script.enabled`). Выключен — модель о скриптах не знает |
| **Правка из скриптов разрешена в конфиге** | Флаг `kb.script.edit-enabled` |
| **Методы записи привязаны к песочнице** | Фактический ответ: записи (`kb.edit`, `kb.create` и их байтовые пары `kb.writeBytes`, `kb.createBytes`) требуют ещё `kb.git.edit-enabled` и рабочего дерева, доступного на запись. Если разрешение есть, а привязки нет — под строками появится пояснение, чего не хватает |

### Время выполнения и бюджеты

Скрипт ограничен по времени (**бюджет по умолчанию** и **потолок**, который модель не может превысить, сколько бы ни попросила) и по объёму работы: сколько файлов и байт можно прочитать, сколько сделать вызовов `kb.*`, сколько символов вернуть и записать в журнал. Бюджеты защищают бэкенд, а не контекст модели: в неё попадают только возвращённое значение и журнал, у которых свои лимиты. Превышение большинства лимитов останавливает прогон с ошибкой `BUDGET` — кроме размера возвращаемого значения: тут скрипт не падает, значение обрезается до лимита `maxResultChars`, а в журнал добавляется предупреждение об обрезке.

### Видимость файлов

Скрипт видит только отслеживаемые файлы репозитория, и поверх этого действуют два списка масок: **скрытые пути** (deny) прячут то, что видно остальным инструментам, а **только эти пути** (allow), если заданы, оставляют видимым лишь совпадающее. По умолчанию оба пусты.

### Пробный запуск

Внизу группы — поле, в котором можно написать скрипт самому и сразу увидеть результат: те же движок, лимиты и формат ответа, что и у модели. Поле открывается готовым примером — он разбирает комментарии в первом попавшемся файле репозитория и показывает, как выглядит обычный скрипт целиком: выбор файла через `kb.files`, чтение через `kb.read`, обычный JavaScript поверх текста, `kb.log` и возврат результата через `return`.

После запуска показываются:

- **счётчики прогона** — сколько файлов и байт прочитано, сколько было вызовов `kb.*`, сколько заняло времени;
- **ошибка**, если скрипт не доработал: её вид (`SYNTAX`, `RUNTIME`, `TIMEOUT`, `BUDGET`), сообщение и строка;
- **журнал** — всё, что скрипт написал через `kb.log`, включая предупреждение об обрезке результата, если оно было;
- **результат** — то, что вернул `return`, в виде JSON; если он превысил `maxResultChars`, это обрезанное значение, а не полное.

> ⚠️ **Пробный запуск всегда read-only.** Методы записи (`kb.edit`, `kb.create`, `kb.writeBytes`, `kb.createBytes`) в него не привязываются, даже если правка из скриптов разрешена: стенд — не место, где в рабочем дереве появляются непросмотренные изменения. Правки делаются в чате, где виден дифф. Если инструмент выключен (`kb.script.enabled=false`), кнопка запуска заблокирована — пример при этом всё равно можно прочитать.

## 6. Группа «Чат»

Параметры истории диалога и контекста модели:

| Параметр | Описание |
|---|---|
| **Пороги суммаризации** | Минимальный и максимальный размер контекста (в токенах) |
| **Таймаут ответа** | Максимальное время ожидания ответа от модели |
| **Число попыток** | Количество попыток переподключения при ошибке |

> 📌 **Примечание:** реальное окно контекста задаётся порогами суммаризации, а не видимым количеством сообщений.

## 7. Копирование значений

При наведении на любое значение параметра появляется кнопка копирования — нажмите, чтобы скопировать значение в буфер обмена.

## 8. Обновление настроек

Все параметры в панели **только для чтения** — они загружаются из конфигурации сервера (`application.yaml` или переменные окружения). Единственное поле, которое можно менять, — текст скрипта в пробном запуске, и он нигде не сохраняется. Для изменения параметров:

1. Отредактируйте `application.yaml` или задайте переменные окружения
2. Перезагрузите приложение
3. Обновите страницу в браузере
