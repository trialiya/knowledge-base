# Администрирование — руководство пользователя

Панель **Администрирование** предназначена для системных операций: просмотр информации о системе, управление индексацией и экспортом документов.

> 📘 **Где найти:** кнопка 🔧 в правой части верхней панели приложения (рядом с кнопкой Настроек).

> ⚠️ **Важно:** доступ к этой панели ограничен и требует соответствующих прав.

## 1. Структура администрирования

Панель разделена на несколько групп операций:

- **Информация о системе** — профиль, БД, версия схемы, репозиторий, учётная запись
- **Операции с индексами** — переиндексация семантического поиска
- **Массовые операции** — экспорт документов

## 2. Информация о системе

Группа **Система** показывает текущую конфигурацию приложения:

### Профиль и окружение

| Параметр | Описание |
|---|---|
| **Активный профиль** | Spring профиль, на котором запущено приложение (например, `h2`, `postgres`, `prod`) |
| **Версия приложения** | Номер версии Knowledge Base |

### База данных

| Параметр | Описание |
|---|---|
| **Тип БД** | Используемая система БД (PostgreSQL 17, H2 для разработки) |
| **URL соединения** | Адрес БД (без учётных данных) |
| **Версия схемы** | Текущая версия миграции Flyway (например, `1.5.0`) |

> 🔒 **Безопасность:** пароли и учётные данные БД никогда не отображаются в интерфейсе.

### Репозиторий и экспорт

| Параметр | Описание |
|---|---|
| **Репозиторий Git** | Путь к репозиторию, индексируемому для поиска по коду |
| **Папка экспорта** | Путь к директории для экспорта документов (`KB_DOCUMENTS_EXPORT_PATH`) |

Если параметр не задан, показывается отметка «не настроено».

### Учётная запись

| Параметр | Описание |
|---|---|
| **Пользователь** | Текущий пользователь системы |
| **Язык интерфейса** | Текущий язык интерфейса (RU/EN) |

## 3. Операции с индексами

Группа **Переиндексация** управляет семантическим индексом (эмбеддинг-векторы):

### Кнопка «Переиндексировать»

Запускает полный пересчёт embedding-векторов для всех документов в базе знаний.

**Когда использовать:**

- После загрузки большого количества новых документов
- После изменения модели эмбеддингов
- После обновления приложения с новыми параметрами семантического поиска
- Если результаты семантического поиска кажутся неточными

**Поведение:**

1. Нажмите кнопку «Переиндексировать»
2. Появится диалог подтверждения
3. Процесс запустится в фоне
4. Во время переиндексации показывается индикатор состояния

> 💡 **Долгая операция:** переиндексация больших баз знаний может занять значительное время. Рекомендуется запускать её вне пиковой нагрузки.

### Параметры очереди эмбеддингов

При переиндексации используются следующие параметры:

| Параметр | Описание |
|---|---|
| **Размер батча** | Количество документов, обрабатываемых за один запрос к модели эмбеддингов |
| **Таймаут** | Максимальное время ожидания обработки батча |
| **Число попыток** | Количество повторов при ошибке |
| **Задержка между попытками** | Время ожидания перед повторной попыткой |

## 4. Массовые операции

Группа **Массовые операции** предоставляет инструменты для работы со всей базой знаний:

### Экспорт всех документов

Выгружает всю структуру документов в файловую систему.

**Компоненты:**

- **Кнопка «Выгрузить»** — запускает экспорт
- **Чекбокс «С метаданными»** — включить/исключить `.yaml` файлы с метаданными
- **Путь выгрузки** — показывает текущий путь экспорта (`KB_DOCUMENTS_EXPORT_PATH`)

**Перед экспортом убедитесь:**

- Переменная окружения `KB_DOCUMENTS_EXPORT_PATH` задана
- У приложения есть права на запись в указанную директорию
- Достаточно места на диске

**Результат экспорта:**

- Все документы сохраняются в формате Markdown (`.md`)
- Метаданные сохраняются в YAML (`.yaml`) если выбран соответствующий чекбокс
- Структура папок соответствует структуре базы знаний
- Все внутренние ссылки преобразуются в относительные пути

**Состояния:**

- 🔄 **Идёт выгрузка** — под операцией видно, сколько узлов обработано и какой пишется сейчас
- ✅ **Готово** — экспорт завершён, показано число записанных файлов
- ❌ **Ошибка** — проверьте `KB_DOCUMENTS_EXPORT_PATH` и права доступа

### Импорт из папки экспорта

Обратная загрузка — две кнопки, а не одна.

**«Сравнить»** читает папку экспорта и базу и показывает список различий. Ничего не записывает: это ответ на вопрос «что изменится, если импортировать». Каждая запись помечена статусом:

| Статус | Что значит |
|---|---|
| **новый** | Есть в папке, в базе нет — импорт создаст узел |
| **изменён** | Есть в обоих, содержимое или заголовок расходятся — импорт перезапишет описание |
| **совпадает** | Изменений нет; такие записи скрыты, пока не включить «Показывать совпадающие» |
| **нет в папке** | Есть в базе, но файла больше нет |

**«Импортировать отмеченное»** применяет ровно то, что отмечено галочками. Отметка документа внутри новой папки автоматически отмечает саму папку — без неё ребёнка некуда положить.

**Удаление** отдельно и по умолчанию выключено: записи «нет в папке» удаляются из базы, только если отметить их **и** включить чекбокс «Удалять из базы отмеченные записи "нет в папке"».

Повторный импорт безопасен: то, что уже совпадает, попадает в «совпадает» и не трогается.

Подробнее о формате и о том, как устроено сопоставление, — см. [Экспорт и импорт документов](экспорт-документов.md).

## 5. Безопасность

Все параметры в панели администрирования собираются избирательно — целиком не отправляется содержимое `Environment`:

✅ **Показывается:**
- Названия и публичные адреса
- Типы БД и версии
- Состояние операций
- Пути без учётных данных

❌ **Никогда не показывается:**
- Пароли и ключи доступа
- JDBC URL с учётными данными
- Bearer-токены MCP-подключений
- Секретные переменные окружения

> 🔒 Названия MCP-подключений показываются для удобства, но ключи и пароли остаются скрытыми.
