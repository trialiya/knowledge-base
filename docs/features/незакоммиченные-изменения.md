# Незакоммиченные изменения — руководство пользователя

Панель **Файлы** умеет показывать не только дерево репозитория, но и то, что в нём изменено и ещё
не закоммичено. Это режим для ревью: посмотреть, что наработал ассистент (или вы сами) с момента
последнего коммита, и открыть каждый файл — целиком или его diff.

> 📘 **Где найти:** вкладка **Файлы**, переключатель **Файлы / Изменения** в левой панели.

## 1. Переключение режима

Над списком слева стоит переключатель из двух половин:

| Половина | Что показывает левый блок |
|---|---|
| **Файлы** | дерево репозитория целиком (режим по умолчанию) |
| **Изменения** | только незакоммиченные файлы |

Режим попадает в адрес — `/files/<путь>?changes=1`, — поэтому ссылкой на конкретное изменение
можно поделиться, и она откроется сразу в режиме ревью. Адрес без `changes` означает обычное
дерево. Переключение не считается переходом: кнопка «Назад» в браузере не отматывает его, ровно
как и сворачивание боковых панелей.

Открытый файл при переключении не теряется: путь в адресе один и тот же, меняется только то, из
чего вы его выбираете.

## 2. Что попадает в список

Список делится на две секции, и порядок этот не случаен.

### Отслеживаемые

Файлы под контролем git — добавленные, изменённые, удалённые, переименованные. Сравнение идёт с
последним коммитом (`HEAD`), поэтому не важно, попала правка в индекс (`git add`) или нет: и то и
другое — «ещё не закоммичено». Файлы, которые ассистент правил инструментами, обычно уже в
индексе и показываются как **A**.

Буква слева от имени — тот же статус, что печатает `git status`:

| Буква | Значение |
|---|---|
| **A** | добавлен |
| **M** | изменён |
| **D** | удалён |
| **R** | переименован (рядом с именем показано старое) |
| **C** | скопирован |
| **U** | не отслеживается (см. ниже) |

Справа в строке — счётчики добавленных и удалённых строк (`+N/−M`), те же, что под ответом
ассистента в чате.

### Неотслеживаемые

Отдельная секция ниже, и появляется она **только если такие файлы есть**. Сюда попадают файлы,
которых git не знает, но которые администратор открыл проекту через `kb.projects[].allow-globs` —
обычно отчёты сборки, логи, черновики. У них нет истории и в коммит они сами не попадут, поэтому
статус у них свой, **U**, а не «добавлен»: разница решает, нужно ли о такой правке рассказывать
отдельно.

Файлы, скрытые `.gitignore`, в список не попадают, даже если `allow-globs` разрешает их читать:
разрешение читать артефакт сборки не делает его изменением, которое стоит ревьюить. Всё
остальное неотслеживаемое тоже остаётся снаружи — открыть такой файл всё равно нечем.

Если незакоммиченного нет вовсе, панель так и говорит: «Незакоммиченных изменений нет».

## 3. Иерархия или плоский список

Кнопка справа от переключателя режима меняет раскладку списка:

- **Плоский список** (по умолчанию) — одна строка на файл, перед именем приглушённым цветом
  стоит его каталог. Незакоммиченных файлов обычно единицы, и так их видно все сразу.
- **Иерархия каталогов** — привычное дерево. Цепочки каталогов с единственным потомком склеены
  в одну строку (`backend/src/main/java` вместо четырёх ступеней подряд), каталоги раскрыты
  сразу: дерево, которое надо разворачивать руками, показало бы при открытии одни имена папок.

Выбор запоминается — он переживает и перезагрузку страницы, и смену проекта. В адрес он не
попадает: адресом делятся тем, **что** открыто, а плоско или деревом читать — личная привычка.

## 4. Оригинал и diff в центре

Клик по строке открывает файл в центральной панели. Что именно показать, панель выбирает сама:

- **изменённый отслеживаемый файл** → сразу **diff**: смотреть в нём хотят изменение;
- **неотслеживаемый файл (U)** → **содержимое**: у него нет «предыдущей версии», весь файл и есть
  новое;
- **удалённый файл (D)** → **diff**, и только он: в рабочем дереве файла уже нет, переключать не
  на что.

В остальных случаях в мета-строке над содержимым стоит кнопка **Diff** — она переключает
оригинал ↔ изменения и запоминает выбор, пока открыт этот файл. Diff показывается в unified-виде,
с номерами строк и той же раскраской, что и изменения под ответом ассистента в чате: один и тот же
патч не должен выглядеть в двух местах по-разному.

Если открыть из этого режима файл, у которого изменений нет (например, перейти по ссылке из чата),
центр скажет «У файла нет незакоммиченных изменений» — это ответ, а не ошибка.

## 5. Что этот режим не делает

Режим **только читает**. Ни закоммитить, ни отменить изменение, ни добавить файл в индекс отсюда
нельзя — для этого есть git в терминале. Правки же в файлы вносит ассистент своими инструментами,
и список обновляется вслед за ними: после правки из чата панель переспрашивает состояние рабочего
дерева сама.
