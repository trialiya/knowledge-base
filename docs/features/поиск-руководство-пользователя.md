# Поиск — руководство пользователя

## 1. Как открыть поиск

Поле поиска живёт в **глобальной шапке приложения**, в верхней части экрана, и видно всегда — из чата, из базы знаний, из файлов. Enter открывает раздел **«Поиск»** с результатами.

Горячей клавиши для открытия поиска нет.

Кнопка **«Обновить»** (↻) в меню «⋮» справа появляется, когда открыт документ, и перезагружает его содержимое; к поиску она отношения не имеет.

## 1а. Где искать: три категории

Слева в разделе «Поиск» выбирается **одна** категория. Вместо галочки у каждой стоит число найденного — по нему видно, стоит ли переключаться.

| Категория | Что ищет | Чем уточняется |
|---|---|---|
| **Файлы** | Содержимое файлов репозитория (`git grep`) | Репозиторий, маска пути, ревизия, регулярное выражение, неотслеживаемые файлы |
| **Документы** | Базу знаний | Режим поиска (см. ниже) |
| **Чаты** | Сообщения и названия чатов | Ничем |

Ревизия и неотслеживаемые файлы вместе не работают: с заданной ревизией поиск идёт по снимку коммита, а в снимке неотслеживаемого нет по определению — галочка в этот момент выключена, и рядом сказано почему. Снимите ревизию, и она вернётся в том же положении, в каком стояла.

Категория по умолчанию — тот раздел, из которого вы искали: из чата ищется по чатам, из базы знаний по документам, отовсюду ещё — по файлам. Выбранную руками категорию повторный Enter не сбрасывает.

Результаты сгруппированы по тому, где нашлись: файл со многими совпадениями остаётся одной карточкой, длинный хвост прячется под «ещё N». Запрос, категория и все фильтры стоят в адресе — выдачей можно поделиться ссылкой, а «Назад» вернёт туда, откуда искали.

Если поиск успел ответить не всё, он говорит об этом строкой над результатами: у файлов есть предел числа совпадений, у чатов — предел просмотра. Уточните запрос или сузьте путь.

## 2. Три режима поиска

Режим относится **только к документам** и выбирается в фильтрах слева, когда выбрана категория «Документы»:

| Режим | Как работает | Когда использовать |
|---|---|---|
| **Keyword** | Поиск по точным словам в названии и содержимом | Знаете точные слова из документа |
| **Semantic** | Поиск по смыслу, даже если слова не совпадают | Не помните точных формулировок |
| **Hybrid** | Объединяет keyword и semantic | Универсальный вариант (по умолчанию) |

## 3. Keyword-поиск

Ищет документы по точному совпадению слов в полях `title` и `description`.

**Как работает:**
- Использует SQL `ILIKE` — регистронезависимый поиск
- Ищет каждое слово запроса отдельно
- Ранжирует результаты: совпадение в названии ценится выше, чем в содержимом
- Показывает сниппет — фрагмент текста вокруг найденного слова

**Пример:** запрос `spring ai` найдёт документы, где есть оба слова — «spring» и «ai» (в любом регистре).

## 4. Semantic-поиск

Ищет документы по смысловой близости, даже если точных слов в документе нет.

**Как работает:**
- Текст запроса преобразуется в эмбеддинг (вектор) с помощью модели эмбеддингов
- Сравнивается с эмбеддингами всех документов через **cosine similarity** в pgvector
- Результаты с similarity ниже порога отбрасываются (порог задан на бэкенде, пользователь не меняет)

## 5. Hybrid-поиск

Объединяет keyword и semantic поиск.

**Как работает:**
- Выполняются оба поиска параллельно
- Результаты объединяются с весами (kwWeight и semWeight заданы на бэкенде)
- Дубликаты (один документ, найденный обоими методами) объединяются

Это режим **по умолчанию** — он даёт наилучшие результаты в большинстве случаев.

## 6. Результаты поиска

Каждый результат показывает:

- **Заголовок** — название документа (кликабельно, открывает документ; поддерживает среднюю кнопку мыши и Ctrl+клик для открытия в новой вкладке)
- **Breadcrumb** — путь от корня до документа (например: `Проект > Архитектура`). Хлебные крошки приходят с бэкенда в поле `parentList` — батчевый CTE-запрос вместо обхода дерева на фронте
- **Сниппет** — фрагмент содержимого с выделенными совпадениями
- **Дата обновления** — когда документ был последний раз изменён

**Как работает открытие:** при клике на результат поиска фронтенд запрашивает полный документ через `GET /api/documents/{id}` (поскольку SearchResult содержит только id, title и snippet), и только после получения полных данных открывает документ в панели просмотра.

## 7. Советы

- **Не помните точных слов?** Используйте **semantic** режим
- **Знаете название документа?** Используйте **keyword** режим
- **В большинстве случаев** оставьте **hybrid** — он даёт лучшее из обоих миров
- **Ищете код?** Категория «Файлы» ищет по содержимому репозитория; маска пути (`backend/**/*.java`) отсекает лишнее быстрее, чем более длинный запрос
- **Нашли в старой ревизии?** Ссылка из результата откроет файл в той же ревизии, в которой он нашёлся
