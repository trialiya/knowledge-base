# Файлы — руководство пользователя

Панель **Файлы** предоставляет навигацию по файлам и папкам репозитория, позволяет просматривать содержимое файлов и интегрировать их в чат.

> 📘 **Где найти:** вкладка **Файлы** в верхнем меню приложения.

## 1. Структура файлов

Левая панель показывает **древовидную структуру репозитория**:

- **Раскрыть/свернуть папку** — клик по стрелке ▶/▼ слева от названия
- **Просмотр файла** — клик по названию файла откроет его содержимое в центральной панели
- **Иконки типов** — иконка файла указывает на его тип (скрипт, конфиг, архив и т.д.)
- **Оранжевая строка** — файл вне git: администратор открыл его проекту через
  `kb.projects[].allow-globs` (обычно это отчёты сборки или логи). Читать и править такой файл
  можно наравне с остальными, но истории у него нет и в коммит он не попадёт. Тем же цветом такие
  файлы помечены и в результатах поиска, а наведение курсора показывает подсказку

## 1а. Выбор проекта

Если проектов настроено несколько, заголовком левой панели становится селектор репозитория —
имя открытого репозитория и есть имя панели. Он принадлежит
разделу «Файлы», а не чату: панель не тянется за активным диалогом — иначе переписка уводила бы вас
из того дерева, которое вы открыли. Обратное направление работает всегда: переход по ссылке на файл
из чата открывает файл **в том проекте, который назвала ссылка**, и переключает панель на него.

Смена проекта возвращает панель в корень репозитория: путь из одного репозитория в другом ничего не
значит. Проект попадает в адрес (`?project=`), поэтому ссылкой на файл конкретного проекта можно
поделиться; адрес без проекта означает проект по умолчанию — так выглядят и все ссылки, написанные
до появления проектов. Если проект из адреса убрали из конфигурации или переименовали, панель
покажет дефолтный вместо ошибки: старой ссылкой всё равно можно пользоваться, а починить её вручную
было бы негде — с единственным проектом селектор не показывается.

Проект, помеченный в списке как **«(недоступен)»**, настроен на сервере, но его репозиторий не
открылся — чаще всего не подключён том. Выбрать его можно, но дерево не покажется: обращения к
такому проекту отвечают отказом, и чинить это нужно на стороне деплоя.

## 1б. Незакоммиченные изменения

Переключатель **Файлы / Изменения** над списком меняет то, что показывает левый блок: вместо
дерева репозитория — только файлы, изменённые с последнего коммита, отслеживаемые и (если проекту
открыты `allow-globs`) отдельной секцией неотслеживаемые. Список можно читать плоско или деревом,
а каждый файл открывать и оригиналом, и как diff.

Подробно — [Незакоммиченные изменения](незакоммиченные-изменения.md).

## 1в. Ветка репозитория

Над переключателем режимов стоит строка с текущей веткой: имя, а рядом — насколько она разошлась с
той веткой, которую отслеживает (`↑` свои коммиты, которых нет в remote, `↓` чужие, которых нет
здесь). Нули не показываются: строка отвечает на вопрос «разошлись ли», а не «на сколько именно».

Особые состояния подписаны прямо у имени:

- **detached** — HEAD стоит на коммите, а не на ветке. Сделанный в таком состоянии коммит не
  переживёт переключения, и панель говорит об этом, а не показывает хэш как имя ветки;
- **нет коммитов** — свежий `git init`: ветка есть по имени, истории ещё нет.

Счётчики считаются по локальным данным: пока не спросить remote, «позади» останется нулём, сколько
бы туда ни попало чужих коммитов. Для этого рядом кнопка **обновить** (`git fetch`) — она забирает
из remote только сведения о ветках, ничего не сливает и ни одного файла не меняет.

Кнопка появляется, только если git-команды разрешены для этого проекта в конфигурации
(`kb.projects[].git-commands`) и рабочее дерево доступно на запись; сама строка с веткой видна
всегда. Если git откажет — например, к remote нет доступа, — панель покажет его собственное
сообщение: по нему и понятно, что чинить.

### Операции над репозиторием

Рядом с кнопкой обновления — меню действий (появляется по тем же правам):

- **переключиться на ветку** из списка локальных веток и **создать новую** от текущей;
- **спрятать изменения** (`stash`) и **вернуть их**;
- **закоммитить** отслеживаемые изменения — те самые, что показывает режим «Изменения», включая
  правки, сделанные ассистентом.

Незакоммиченная работа не теряется молча ни в одном из сценариев. Переключение, которое затёрло бы
изменённые файлы, git отклоняет и называет их — дальше решает пользователь: спрятать в stash или
закоммитить. Возврат из stash, который конфликтует с текущим деревом, оставляет stash на месте.
Коммит требует, чтобы у репозитория была настроена личность (`git config user.name` и
`user.email` на хосте) — подставлять её за владельца деплоя приложение не станет.

**Втянуть и отправить.** В том же меню — **втянуть изменения** (`pull`) и **отправить**
(`push`). Pull работает только «в перемотку»: если и здесь, и в remote появились свои коммиты,
он откажет — сливать разошедшиеся истории по клику приложение не станет, это решение принимают
осознанно. Push отправляет текущую ветку и никогда не форсируется: отказ означает, что remote ушёл
вперёд, и лечится он pull'ом, а не перезаписью чужой работы. У ветки, созданной здесь же, upstream
проставится сам, если remote у репозитория один.

Push — отдельное разрешение (`git-commands.push-enabled`): пункт появляется, только если деплой
позволил этому проекту публиковать содержимое наружу. Остальные команды могут быть при этом
включены.

**Откат файла.** В режиме «Изменения» у каждого отслеживаемого файла есть кнопка отката: файл
вернётся к закоммиченному состоянию. Это единственная операция, которая уничтожает работу, поэтому
она берёт один файл и спрашивает подтверждение с его именем — и учтите, что вместе с вашими
правками пропадут и сделанные ассистентом.

**Незавершённый merge.** Если merge остановился на конфликте, над веткой появляется полоса с числом
конфликтующих файлов и кнопкой **прервать merge**. Пока полоса висит, в файлах лежат маркеры
конфликта — их видит и ассистент. Разрешить конфликт можно правкой файлов и коммитом, а прерывание
всегда возвращает дерево в состояние до merge.

Полоса появляется только на merge. Прерванный rebase, cherry-pick, revert или bisect она не
показывает — выйти из них `merge --abort` не может, и предлагать кнопку, которая ответит отказом,
хуже, чем не предлагать никакой: такие состояния закрываются на хосте.

## 2. Поиск файлов

В верхней части панели находится **поле поиска**:

- **Fuzzy-поиск** — введите имя или часть пути файла, появится отфильтрованный список
- **Результаты** — файлы, совпадающие с поисковой фразой
- **Escape** — очистить поиск и вернуться к полной структуре

### Как работает поиск

- Ищет по названиям файлов и папок
- Не чувствителен к регистру
- Поддерживает частичное совпадение (например, `docker` найдёт `docker-compose.yaml`)

## 3. Просмотр файла

При клике на файл в центральной панели показывается его содержимое:

### Шапка файла

- **Путь** — полный путь от корня репозитория
- **Размер и строки** — размер файла в байтах и количество строк
- **Кнопка копирования** — скопировать содержимое в буфер обмена
- **Кнопка вставки в чат** — быстро добавить файл в сообщение чата

### Просмотр содержимого

- **Подсвечивание синтаксиса** — для поддерживаемых языков (Java, Python, JavaScript, YAML, JSON, SQL и др.)
- **Номера строк** — слева отображается номер строки для удобной ссылки
- **Длинные строки** — горизонтальный скролл внутри панели
- **Бинарные файлы** — показывается сообщение «Бинарный файл, просмотр недоступен»
- **Markdown-рендеринг** — для `.md` файлов доступна кнопка переключения между просмотром кода и Markdown-рендерингом (👁 для просмотра, { } для кода)

## 4. Интеграция с чатом

Основной способ добавления файла в чат — использование триггера `/file`.

### Триггер `/file`

Используется в поле ввода чата:

1. Откройте чат и нажмите на поле ввода сообщения
2. Введите `/file ` (или русский синоним `/файл`)
3. Начните набирать имя файла — появится выпадающий список (fuzzy-поиск)
4. Выберите файл стрелками ↑↓ и нажмите Enter — чип файла добавится в поле

Подробнее — см. [Чат — руководство пользователя](чат-руководство-пользователя.md#14-вставка-файлов-репозитория-file).

### Режимы добавления

Файл можно добавить двумя способами:

| Режим | Токен | Результат |
|---|---|---|
| **С содержимым** | `⟦file:PATH⟧` | Полный файл вставляется как fenced code block |
| **С диапазоном строк** | `⟦file:PATH#FROM-TO⟧` | Только строки FROM-TO (1-based, включительно) |
| **Только ссылка** | `⟦ref:PATH⟧` | Добавляется как backtick-ссылка `` `PATH` `` |

## 5. Превью файла в чате

При добавлении файла в сообщение чата:

- **Чип файла** — показывает название и путь к файлу в поле ввода
- **Клик на чип** — открывает полноэкранное превью содержимого
- **Кнопки режима** — переключение между просмотром содержимого и ссылкой
- **Удаление чипа** — нажмите × на чипе, чтобы убрать файл из сообщения

## 6. Копирование пути

Чтобы скопировать путь к файлу:

1. Откройте файл в панели
2. Используйте триггер `/file` в чате для вставки — путь скопируется как часть чипа файла
3. Или выберите и скопируйте путь вручную из адреса файла в шапке

## 7. Фильтры по типам

Некоторые типы файлов могут быть скрыты для удобства (например, node_modules, .git):

- **Встроенные исключения** — обычно исключаются папки с зависимостями и артефактами сборки
- **Показать всё** — опция (если есть) для отображения скрытых файлов

## 8. Горячие клавиши

| Клавиша | Действие |
|---|---|
| **↑↓** | Навигация по файлам в списке |
| **Enter** | Открыть файл |
| **Escape** | Закрыть превью / очистить поиск |

## 9. Обработка ошибок

- **Файл не найден** — если файл был удален, показывается сообщение об ошибке
- **Ошибка загрузки** — если репозиторий недоступен, показывается ошибка соединения
- **Бинарный файл** — для изображений и архивов показывается `⚠️ Бинарный файл, просмотр недоступен`
