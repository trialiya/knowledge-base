# Логи и тесты после #460 и #470

## Логи, которые `ToolCallLog` теперь дублирует

#460 собрал журнал вызовов инструментов в `tools/ToolCallLog` (одна строка в
INFO на вызов, целиком — в DEBUG) и перевёл `log.info` в `functions/*` в
DEBUG. В сервисах под инструментами осталось:

- `service/document/DocumentService.java:699-707` — `grepDocuments: pattern=…
  regex ctx documentId — N block(s)` в INFO: повторяет аргументы, которые
  `ToolCallLog.java:51-58` уже пишет. В DEBUG.
- `service/SearchAgentService.java:156` — `search sub-agent start: task='…'`
  (аргумент инструмента, 160 символов) и `:225` — `done … report='…'` с текстом
  отчёта. Для вызывающего инструмента `ToolCallLog` пишет оба. `:170` (предел
  итераций) оставить.
- `DocumentService.java:463` и `DocumentSummaryService.java:76` — одна и та же
  фраза `Summarised document id={} title='{}'`: каждая сводка в логе дважды.
- `service/chat/script/ScheduledScriptService.java:221` — `finished: {}` с
  `result.getFormattedResponse()`: весь результат скрипта в INFO. Это
  плановые прогоны, не вызовы инструмента, но дамп содержимого — то, от чего
  #460 уходил.
- `service/embedding/EmbeddingService.java:251` — `Calling embedding api: N
  items` на каждый вызов.
- `service/file/git/GitWriter.java:114, :151, :188, :240, :327` — INFO на каждую
  запись, только пути и счётчики. Для REST и скриптов ещё полезно, для
  инструментов дублирует `ToolCallLog`. На усмотрение.

## Тест без замка на логгер

#470 повесил `@ResourceLock("message-logging-advisor-log")` на
`MessageLoggingAdvisorTest`, `CompactServiceTest`, `CompactPromptCacheTest`:
первый поднимает уровень логгера адвайзера и вешает appender, остальные
пишут в тот же логгер параллельно. Комментарий замка
(`MessageLoggingAdvisorTest.java:46-48`): «общий для каждого класса, чьи
запросы проходят через `MessageLoggingAdvisor`».

`service/chat/memory/ReasoningStreamTest.java:157` строит настоящую цепочку
через `new ChatConfig().chatClient(...)`, в ней `MessageLoggingAdvisor`
(`ChatConfig.java:666`), замка нет. Та же гонка, что воспроизводилась «один
раз из трёх».

`PrePersistedUserMessageTest:120-135` собирает цепочку без адвайзера,
`ChatRun*`-тесты мокают `ChatClient` — не затронуты. Другого глобального
состояния в тестах (`System.setProperty`, `Locale.setDefault`,
`TimeZone.setDefault`, `LoggerContext`) нет.

Spring AI / MCP SDK.
