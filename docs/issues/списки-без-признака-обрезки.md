# Списки с пределом без признака обрезки

#475 завёл `GitCommitSearchResult { commits, truncated }` с доводом: «список без
признака обрезки не отличает „нет“ от „не дошли“». #488 и #492 довели это до
`ToolResult.truncated` у `getCommitLog` и `grepContent`, до `kb.grep` и
`/api/git/commits/search`, назвали пределы в описаниях инструментов и подключили
`limit` к keyword-поиску. Осталось два пункта.

## 1. Списки без предела вовсе

`getChatAttachments`, `getDocumentAttachments` (`functions/AttachmentFunction.java:51`),
`getFileTree` (`functions/GitFunction.java:130`), `kb.files`
(`service/chat/script/KbScriptApi.java:120-128`). У `getUncommittedChanges`
патчи ограничены `PatchBudget` (3000 строк на ответ), но число файлов — нет:
рабочее дерево с тысячей изменённых файлов уходит модели целиком списком.

Что сделать: предел по числу записей и `ToolResult.truncated`, как у
`getTreeSkeleton` (1000 узлов, целыми уровнями) из #484.

## 2. Пределы без цены

Из #477: «предел в 2000 был выбран на глаз», и в комментарии теперь написано, во
что обходится 20 000. Измеренная цена есть только у `CommitSearch.SCAN`. Просто
названы, без довода: `Diffs.MAX_DIFF_LINES = 500` (`Diffs.java:33`),
`FileViews.HEAD_LINES = 200` / `TAIL_LINES = 50` (`FileViews.java:19-22`),
`RepoFiles.MAX_FILE_SIZE = 512 КБ` (`RepoFiles.java:25`),
`GitCommands.MAX_OUTPUT_CHARS = 4000` (`GitCommands.java:80`),
`ResultLimit.OBJECT_DEPTH = 2` (`ResultLimit.java:24`),
`ScriptProperties.DEFAULT_MAX_CALLS = 2000`, и новые из #484 — `PatchBudget`
(3000 строк, 20 хешей), `GrepLines` (500 символов на строку). Не задача
«измерить всё», а правило для следующего, кто их тронет: цифра без комментария
о цене — повод замерить.
