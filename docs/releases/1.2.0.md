# 1.2.0

Что вошло в релиз и что осталось закрыть до тега `v1.2.0`. Состав релиза для
тех, кто ставит приложение, — по-английски в `CHANGELOG.md`; что обновление
требует от того, кто его делает, — в `UPDATING.md`. Здесь внутренняя сторона
выпуска.

Выпуск идёт так же, как 1.1.0: кандидатов ставят не на той машине, где
собирали, и только потом — тег `v1.2.0`. Что найдёт кандидат, получает свою
секцию в `CHANGELOG.md` под следующим номером.

- `1.2.0-RC1` (10.10) — история изменений: ссылки на коммиты (#466), поиск
  коммитов (#475, #477, #492, #497), blame в «Файлах» и для модели (#478,
  #483, #485, #490, #499), «Когда появилось» (#500), лента истории (#501),
  сравнение ревизий (#511); уровень рассуждений в чате и у сабагента (#507,
  #512, #513); ответы инструментов модели без лишних полей и с признаком
  обрезки (#480, #484, #488).

## 0. Что сделано

- **RC1:** версия `1.2.0-RC1` в `build.gradle`, `backend/build.gradle`,
  `frontend/package.json` и в строке «Current version» в README; секция
  `[1.2.0-RC1]` в `CHANGELOG.md` со своими «Upgrading» и «Build»; раздел
  `## Unreleased` в `UPDATING.md` закрыт номером `1.2.0-RC1`. Из него убраны
  две записи — о форме ответа `/api/git/commits/grep` и о полях ханка
  `/api/git/files/blame`: оба эндпоинта появились после `v1.1.0` (#475,
  #478), и обновляющийся с 1.1.0 прежней формы не видел. Остались четыре:
  `{commits, truncated}` у `/commits` и `/commits/search`,
  `kb.search.keyword.limit`, пустые поля в REST-ответах git и поиска, итог
  скрипта по расписанию в DEBUG. README и `docs/проект/введение.md`: blame,
  лента истории, сравнение ревизий, поиск по коммитам, уровень рассуждений.
- После `v1.1.0` проверены все влитые PR (#466–#515): критичных ошибок нет.
  Ежедневная визуальная сборка на `main` падала с 7.10 — устарели эталоны
  карточек поиска (кнопка «Когда появилось», #500) и «Настройки → Модели»
  (уровни рассуждений, #512), а эталонов `blameCall` и `lineOriginCard` не
  было вовсе; пересняты и заведены в этом же выпуске. Не в CHANGELOG —
  пользователь этого не видит: разбиение `GitService` (#487),
  `TextChunker.defaults()` (#489), упрощения blame и поиска коммитов (#494,
  #495, #497), перенос фронтенда на общие компоненты (#493), лишние тесты
  (#498), правило о ревью по этапам в `CLAUDE.md` (#502).

## 1. Обязательное до `v1.2.0`

| Пункт | Почему |
| --- | --- |
| Прогнать `./run/test.sh pre-pr` и `smoke` на чистом клоне | Единственная проверка, которая ловит расхождение сборки и скриптов запуска |
| Поднять RC поверх базы 1.1.0, а не с нуля | Новые таблица `tool_call_full_result` и колонки `chat_topic.reasoning`, `chat_pending_message.reasoning` — миграции должны лечь на живую схему |
| Blame и «Когда появилось» на большом репозитории и на репозитории без `.git-blame-ignore-revs` | Blame идёт подпроцессом `git`, «Когда появилось» — обходом JGit; оба упираются в дедлайн и предел обхода |
| Уровни рассуждений на каждой модели деплоя, где они заданы | Уровень пишет `reasoning-effort` и/или `extra-body`; эндпоинт, который не знает поле, отвергнет запрос (#512) |
| Тег `v1.2.0-RC1`, JAR, GitHub Release с пометкой pre-release | Выпуск делается руками (решение по CI) |
