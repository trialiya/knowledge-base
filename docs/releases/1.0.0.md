# 1.0.0

Что вошло в релиз, что решено не делать и что осталось закрыть до тега
`v1.0.0`. Состав релиза для тех, кто ставит приложение, — по-английски в
`CHANGELOG.md`; здесь внутренняя сторона выпуска.

RC-шага не было: `1.0.0-RC1` никому не отгружался — тег не проставлялся, —
поэтому версия стала `1.0.0` без промежуточного выпуска, и двух секций про один
и тот же состав в `CHANGELOG.md` не появилось.

## 0. Что сделано

- Версия проекта поднята до `1.0.0` (`build.gradle`, `backend/build.gradle`,
  `frontend/package.json`).
- Имя собранного JAR зафиксировано: `bootJar.archiveFileName = 'kb.jar'` в
  `backend/build.gradle`. Раньше оно несло версию и было выписано литералом в
  `run/run.sh`, `run/run.bat`, `run/run.ps1` и `scripts/playwright-smoke.js` —
  то есть каждая смена версии молча ломала запуск и smoke и требовала правки
  документации. Теперь путь один и тот же во всех релизах; сама версия видна в
  манифесте (`Implementation-Version`) и в админ-панели. `docker/Dockerfile`
  тоже берёт `kb.jar` по имени, а не маской `*.jar`.
- `spring.application.name` больше не `kb-demo`, а `knowledge-base` — то же
  значение, что и в фолбэке `ServerEnvironment`.
- Из git убран кэш vitest (`node_modules/.vite/…`), `.gitignore` расширен до
  `node_modules/` в любом каталоге, не только во `frontend/`.
- `.index.md` в `docs/`, `docs/features/` и `docs/todo/` приведены к тому, что
  реально лежит на диске (были ссылки на несуществующие папки, дубль и
  пропущенные документы).
- Из `docs/todo/` убраны завершённые планы и описания снятого кода.
- `spring.flyway.validate-on-migrate` переведён в `true` (дефолт самого Flyway):
  отредактированная задним числом миграция теперь роняет старт, а не разводит
  схему с репозиторием молча. Заодно снят одноимённый override в
  `AbstractPostgresIntegrationTest` — иначе интеграционные тесты единственные
  проходили бы мимо проверки, которую мы включаем.
- Починен `docker/Dockerfile`: он копировал `frontend/postcss.config.js`,
  которого в репозитории нет (и не было) — `docker build` падал на этой строке,
  то есть основной быстрый старт из README не собирался вообще. Заодно в
  build-стадию поехали `gradle.lockfile` и `backend/gradle.lockfile`: локи
  нестрогие, и без них образ молча собирался бы на других версиях зависимостей,
  чем проверил CI. `kb.jar` берётся по имени, а не маской `*.jar`.
- Заведён `UPDATING.md` — что обновление требует от того, кто его делает
  (ломающее, deprecation, шаги миграции). Заполняется в том же пул-реквесте,
  который вносит изменение: шаблон PR спрашивает про запись, `CLAUDE.md`
  описывает правило. Две записи в нём уже есть — путь к JAR и валидация Flyway.
- Секция `1.0.0` в `CHANGELOG.md` закрыта датой, а ломающая её часть собрана из
  `UPDATING.md` — первый прогон того порядка, ради которого этот файл и заведён.
- Заведён `CHANGELOG.md` (по-английски, как и README) с описанием состава
  релиза и раздела «Known limitations»; README актуализирован под него —
  добавлены разделы про git-команды пользователя, `runScript`, несколько
  репозиториев, сжатие контекста и i18n, поправлены категории поиска, ключ
  `kb.projects[].path` вместо устаревшего `kb.git.project-path` и предупреждение
  про `/h2-console`.

## 1. Обязательное до `v1.0.0`

| Пункт | Почему |
| --- | --- |
| Прогнать `./run/test.sh pre-pr` и `smoke` на чистом клоне | Единственная проверка, которая ловит расхождение сборки и скриптов запуска |
| Собрать образ и проверить `docker compose -f docker-compose-h2.yaml up` и `docker compose up` с нуля | Быстрый старт из README — первое, что увидит пользователь релиза. Сборка образа в веб-песочнице недоступна: `apk add nodejs npm yarn` не достаёт до репозитория Alpine, поэтому дальше строки с `COPY` образ здесь не проверить — нужен прогон в обычном окружении |
| Проставить тег `v1.0.0`, собрать JAR, оформить GitHub Release | Выпуск делается руками (решение по CI). Ссылки внизу `CHANGELOG.md` уже указывают на этот тег |

## 2. Желательное, но не блокирующее

- **Крупные файлы под разделение** (правило «~500 строк кода на бэкенде,
  ~300 на фронте» из `CLAUDE.md`): `GitService` (894), `DocumentFunction` (681),
  `DocumentService` (675), `icons/index.jsx` (555), `useKnowledgeBase.js` (471),
  `ChatWindow.jsx` (469). Делятся по правилу «migrate on touch», а не отдельным
  проходом перед релизом — рефакторинг на RC добавляет риска больше, чем снимает.
- **Squash миграций** (29 Postgres / 21 H2) в один baseline. Соблазнительно
  перед 1.0.0, но ломает любую уже развёрнутую инсталляцию — делать только если
  таких нет, и отдельным PR.

## 3. Рассмотрено и оставлено как есть

Решения приняты сознательно — не поднимать заново:

- **Дефолтные `admin`/`admin`** (`kb.security`) остаются. Названы в README и в
  разделе Known limitations `CHANGELOG.md`; менять их — дело деплоя.
- **`/h2-console` вне HTTP Basic** в профиле `h2` остаётся: вход в саму консоль
  всё равно требует JDBC-логина, а профиль рассчитан на локальную разработку и
  демо. Так же это описано в `SecurityConfig`.
- **Опечатка `V2026.05.22__system_documecnts.sql`** остаётся. Переименование
  меняет `description` в `flyway_schema_history` — и с включённой валидацией
  цена ошибки только выросла.
- **Крупные файлы и squash миграций** — см. §2.

## 4. Проверено и трогать не нужно

- Секретов в репозитории нет: `sk-xxxx…` в `docker/example.env` и
  `run/application.yaml` — плейсхолдеры.
- `TODO`/`FIXME`/`@Deprecated` в коде отсутствуют.
- Нет неиспользуемых модулей фронта, неимпортированных CSS и «мёртвых» классов
  бэкенда (кандидаты из поиска — бины Spring).
- Локали `en`/`ru` совпадают ключ в ключ; расхождение `_few`/`_many` — это
  правила множественного числа русского, а не пропуск.
- `billing` в примерах конфигурации — сквозной пример второго проекта, он же
  в документации; это не утечка чужого имени.
